## القرار المعتمد

يعتمد مشروع ALI-QX خارطة تنفيذ متسلسلة من المرحلة **0 إلى المرحلة 9**. تُنفذ المراحل بالترتيب، ولكل مرحلة بوابة قبول واختبارات. لا يبدأ العمل في المرحلة التالية قبل إغلاق الحالية والتحقق من نتائجها.

المرحلة 9 (Windows) مؤجلة بقرار المستخدم، ولا يبدأ تنفيذها قبل إكمال بقية المشروع وإعادة فتح القرار صراحةً. عند الوصول إلى تلك النقطة يُعاد تقييم الحاجة إلى Windows؛ ولا يُفترض أن توصيل الكمبيوتر شرط لاستكمال المشروع. يبقى التخطيط المعماري الشامل لبرنامج Q Ali QX مؤجلاً إلى أن يعلن المستخدم اكتمال العمل الحالي ويطلب بدء التخطيط.

- Node.js 22 أو أحدث، دون فرض إطار عمل خارجي.
- توليد `index.html` و`styles.css` و`app.js` من QIR V1 صالح.
- لا توسعة لقواعد QX أو الأوامر المفعّلة.

### نطاق المكونات والتكامل المثبت

- **DATA:** الأوامر `DATA.ADD` و`DATA.REMOVE` و`DATA.COUNT` موجودة في مسارات التحليل والتنفيذ. بقي `DATA.GET` مؤجلاً ومعطّلاً عمداً بسبب عدم وجود نوع آمن معتمد للقيم في mixed lists؛ لم يُفعّل ضمن هذا الإغلاق.
- **PROCESS:** الأوامر `PROCESS.ADD` و`PROCESS.CALCULATE` و`PROCESS.COMPARE` مسجلة ومفعّلة ولها مسارات تحليل وتنفيذ.
- **UI:** المكونات الثابتة الحالية هي `UI.CONTAINER` و`UI.TEXT_BLOCK` و`UI.HEADING`، مع دعم شجرة UI الثابتة. أصبح Web Backend يتحقق من سجل lifecycle ويحل الإصدارات عبر exact pins حسب `(type, contractVersion, registryRelease)`، ويحافظ على تعدد إصدارات النوع نفسه ويعرض الإصدار المثبت بدقة. تتضمن السياسة رفض الإصدارات retired أو unsupported، والتحذير عن deprecated-but-supported.
- **INTEGRATION:** وسيط الصلاحيات والحدود والمهل ومسار VM غير المتزامن موجودان. لا يوجد موصل إنتاجي لخدمة خارجية محددة، ولا اتصال شبكي من static Web Backend؛ لذلك لا يُعد هذا الإغلاق إثباتاً لاكتمال موصل إنتاجي.
- **حدود إبطال الإصدارات:** تُتحقق سياسة lifecycle من snapshot يملكه المضيف وقت البناء. لا يتم تحديث سياسة الإبطال تلقائياً أثناء تشغيل أصول المتصفح الثابتة؛ يتطلب تطبيق تغيير host revocation إعادة بناء وإعادة تحقق قبل التوزيع أو التشغيل وفق السياسة الجديدة.
- يقتصر إثبات UI هنا على المكونات الثابتة الثلاثة الحالية والعقود المعتمدة، ولا يعني اكتمال جميع المكونات التفاعلية أو أي مكونات مستقبلية.

**حدود الإثبات:** نجاح CI يثبت الاختبارات والبوابات المذكورة على الرؤوس المحددة؛ ولا يثبت وجود موصل إنتاجي أو اتصال شبكي أو اكتمال جميع إمكانات UI المستقبلية. لم يُدّعَ تشغيل اختبارات محلية ضمن هذا الإغلاق.

**قرار التسلسل:** أُغلقت المرحلة السادسة. لا يبدأ تنفيذ المرحلة السابعة تلقائياً بهذا التحديث؛ تبقى المرحلة السابعة كما هي في الخارطة، ويبدأ العمل فيها عند طلب المستخدم. لم يتم دمج أو إغلاق PR #6 أو PR #8.
