# ALI-QX — قرار تثبيت خارطة التنفيذ 0–9

**التاريخ:** 2026-11-08  
**المستودع:** `alisrm73/ALI-QX`  
**المرجع الأساسي للخارطة:** `QX/README.md`

## القرار المعتمد

يعتمد مشروع ALI-QX خارطة تنفيذ متسلسلة من المرحلة **0 إلى المرحلة 9**. تُنفذ المراحل بالترتيب، ولكل مرحلة بوابة قبول واختبارات. لا يبدأ العمل في المرحلة التالية قبل إغلاق الحالية والتحقق من نتائجها.

بعد إكمال المرحلة 9، نبدأ مرحلة التخطيط المعماري الكامل للمشروع قبل الانتقال إلى التوسع التنفيذي اللاحق. لا يبدأ هذا التخطيط الآن، ولا يُستخدم سبباً لتجاوز مراحل الخارطة 0–9.

## بوابة المرحلة الخامسة

- Node.js 22 أو أحدث، دون فرض إطار عمل خارجي.
- توليد `index.html` و`styles.css` و`app.js` من QIR V1 صالح.
- لا توسعة لقواعد QX أو الأوامر المفعّلة.
- دعم تعليمات QIR V1 المنفذة حالياً، وعرض قيم globals الناتجة كنص آمن.
- رفض المصدر غير الصحيح وQIR غير الصالح قبل توليد الأصول.
- عدم تضمين وصول للشبكة أو ملفات المضيف أو تنفيذ ديناميكي للكود.
- ثبات المخرجات للمدخلات نفسها.
- اجتياز اختبارات المشروع وCI قبل اعتبار المرحلة مكتملة.
- لا يبدأ العمل في المرحلة السادسة قبل إغلاق المرحلة الخامسة.


## إغلاق المرحلة الخامسة — Web Backend

**الحالة: مكتملة ومدمجة في `main` بتاريخ 2026-11-09.**

تحققت بوابة القبول وفق الأدلة التالية:

- توليد ملفات `index.html` و`styles.css` و`app.js` من QIR صالح.
- أضيف تفاعل متصفح صريح عبر زر **Run QX program**؛ لا يبدأ التنفيذ تلقائياً عند تحميل الصفحة، وتبدأ كل ضغطة تشغيلاً جديداً.
- اختبارات Chromium الحقيقية غطّت عدم التشغيل التلقائي، والتشغيل بالضغط، وإعادة التشغيل دون تكرار المخرجات، وإظهار أخطاء وقت التشغيل، مع الحفاظ على عرض شجرة UI الثابتة.
- أضيفت اختبارات لثبات ملفات البناء حرفياً عند تكرار المدخلات نفسها، ورفض QIR غير الصالح قبل توليد الأصول.
- نجحت GitHub Actions على رأسي PR #22 وPR #23: تحقق QIR للمرحلة 3، والتحقق من VM للمرحلة 4، والتحقق في المتصفح للمرحلة 5.
- دُمج PR #22 بالالتزام `b9e352e69a67636534f29521f22689ed6849091f`، ثم PR #23 بالالتزام `42e5e9821435cbc5d0ec2b6423b08a41ff9bc17b`.
- تحقق أن `main` يطابق التزام دمج PR #23 `42e5e9821435cbc5d0ec2b6423b08a41ff9bc17b`.

**حدود الإثبات:** هذه النتائج تثبت بوابة Web Backend المحددة في هذه الخارطة، ولا تعني اكتمال لغة QX أو مكتبة المكونات أو موصلات التكامل الإنتاجية أو دورة بناء المشاريع والتسليم. لم يُدّعَ تشغيل اختبارات محلية ضمن هذا الإغلاق.

**قرار التسلسل:** أصبح بدء المرحلة السادسة مسموحاً بعد هذا الإغلاق، لكنه لا يعني أن المرحلة السادسة قد بدأت أو أن طلبات الدمج القديمة الخاصة بها قد دُمجت.

## قرارات الحماية

لا حذف أو نقل أو استبدال أو إعادة هيكلة لملفات أو مكونات قائمة دون إذن صريح. هذه المرحلة تضيف Backend مستقلًا ولا تغير دلالات QX V1 أو سجل الأوامر.


## سجل المصدر والتمييز

أسماء المراحل ونطاقاتها مستمدة من خارطة التنفيذ في `QX/README.md`. أما ترتيب المراحل 0–9، وقرار بدء التخطيط المعماري الكامل **بعد إغلاق المرحلة 9**، فهما قراران معتمدان من المستخدم. يثبت هذا السجل حالة التنفيذ الحالية دون تغيير مواصفات QX V1 أو عقود اللغة.
