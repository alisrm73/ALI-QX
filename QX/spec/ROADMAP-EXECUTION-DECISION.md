# ALI-QX — قرار تثبيت خارطة التنفيذ 0–9

**التاريخ:** 2026-11-08  
**المستودع:** `alisrm73/ALI-QX`  
**المرجع الأساسي للخارطة:** `QX/README.md`

## القرار المعتمد

يعتمد مشروع ALI-QX خارطة تنفيذ متسلسلة من المرحلة **0 إلى المرحلة 9**. تُنفذ المراحل بالترتيب، ولكل مرحلة بوابة قبول واختبارات. لا يبدأ العمل في المرحلة التالية قبل إغلاق الحالية والتحقق من نتائجها.

بعد إكمال المرحلة 9، نبدأ مرحلة التخطيط المعماري الكامل للمشروع قبل الانتقال إلى التوسع التنفيذي اللاحق. لا يبدأ هذا التخطيط الآن، ولا يُستخدم سبباً لتجاوز مراحل الخارطة 0–9.

## المراحل المعتمدة

| المرحلة | النطاق | الحالة |
|---|---|---|
| 0 | إغلاق توافق Lexer / Parser | مكتملة |
| 1 | تثبيت Unicode 18.0.0 | مكتملة |
| 2 | سجل الأوامر والتحليل الدلالي | مكتملة |
| 3 | تصميم QIR والتحقق منه (QIR V1) | مكتملة ومدمجة في `main` |
| 4 | QX Virtual Machine (VM) | مكتملة ومدمجة في `main` |
| 5 | Web Backend | قيد التنفيذ على `feature/phase5-web-backend` |
| 6 | مكتبة المكونات والتكامل | لم تبدأ |
| 7 | بناء المشاريع والاختبار والتسليم | لم تبدأ |
| 8 | QX Studio على Android | لم تبدأ |
| 9 | Windows | لم تبدأ |

## بوابة المرحلة الخامسة

- Node.js 22 أو أحدث، دون فرض إطار عمل خارجي.
- توليد `index.html` و`styles.css` و`app.js` من QIR V1 صالح.
- لا توسعة لقواعد QX أو الأوامر المفعّلة.
- دعم تعليمات QIR V1 المنفذة حالياً، وعرض قيم globals الناتجة كنص آمن.
- رفض المصدر غير الصحيح وQIR غير الصالح قبل توليد الأصول.
- عدم تضمين وصول للشبكة أو ملفات المضيف أو تنفيذ ديناميكي للكود.
- ثبات المخرجات للمدخلات نفسها.
- اجتياز اختبارات المشروع وCI قبل اعتبار المرحلة مكتملة.
- لا يبدأ العمل في المرحلة السادسة قبل إغلاق المرحلة الخامسة.

## قرارات الحماية

لا حذف أو نقل أو استبدال أو إعادة هيكلة لملفات أو مكونات قائمة دون إذن صريح. هذه المرحلة تضيف Backend مستقلًا ولا تغير دلالات QX V1 أو سجل الأوامر.
