# المجموعة الهندسية الثالثة — حدود التوافق وخطة العقود V1

**الحالة:** مسودة هندسية؛ اتجاه البناء معتمد، لكن عقود الرموز الستة وتواقيعها لم تعتمد بعد.  
**المستودع:** `alisrm73/ALI-QX`  
**الفرع:** `audit/geometric-language-alignment`  
**النطاق:** المجموعة الثالثة فقط: SCREEN, PANEL, BLOCK, WINDOW, BUTTON, LAYOUT.

## 1. القرار المعماري المعتمد

تعتمد المجموعة الثالثة طبقة اللغة الهندسية فوق جسر الواجهة الموجود `UI.TREE`، ولا تنشئ نظام واجهات موازياً.

- تبقى شجرة الواجهة بيانات وصفية Declarative وليست شيفرة قابلة للتنفيذ.
- يظل حل المكونات وإصداراتها من اختصاص سجل المضيف Host Registry.
- يظل ملف `qx.ui-lock.json` هو مرجع تثبيت الإصدارات الدقيقة للمشروع.
- لا يحدث أي تحديث تلقائي للإصدارات أو استبدال صامت للمكونات.
- لا تُمنح عناصر الشجرة صلاحيات DOM أو الملفات أو الشبكة أو التخزين أو التنقل.
- التفاعل والأحداث ومعالجاتها خارج الإصدار الأول من تنفيذ المجموعة الثالثة.
- لا يُسمح بـHTML أو JavaScript أو callbacks أو `eval` أو `Function` أو `innerHTML` أو CSS اعتباطي قادم من المشروع.

هذا القرار يعتمد البنية الموجودة في:
- `QIR-UI-COMPONENT-TREE-EXTENSION-1.4.md`
- `PHASE-6-UI-COMPONENT-TREE-CONTRACT.md`
- `PHASE-6-UI-REGISTRY-VERSIONING-CONTRACT.md`

## 2. الحالة التقنية الحالية التي تم التحقق منها

### 2.1 جسر QIR

الأمر الحالي `UI.TREE(TXT)`:
- تعليمة Statement-only.
- يأخذ وسيط TXT واحداً يحتوي JSON لغلاف `QX.UI.TREE`.
- يُخفض إلى `COMMAND_CALL` ضمن QIR 1.4.
- لا يغير سلوك QIR 1.0–1.3.

### 2.2 بنية الشجرة

الغلاف الحالي:
```json
{
  "schema": "QX.UI.TREE",
  "version": "1.0",
  "children": []
}
```

عقدة المكوّن الحالية تتطلب:
`kind, id, type, version, props, children`.

عقدة النص الحالية تتطلب:
`kind, value`.

الترتيب محفوظ، ومعرّفات المكونات فريدة على مستوى الشجرة، والحقول غير المعروفة مرفوضة. يجري رفض الشجرة كاملة قبل العرض عند فشل التحقق.

### 2.3 سجل المكونات الحالي

السجل المضيف الحالي يحتوي الإصدارات الثابتة التالية:

| النوع | الإصدار | طبيعة العرض |
|---|---:|---|
| `UI.CONTAINER` | `1.0.0` | حاوية ثابتة، وفق سياسة أطفال الإصدار القديم |
| `UI.CONTAINER` | `1.1.0` | حاوية ثابتة تسمح أيضاً بـ`UI.DIVIDER` |
| `UI.TEXT_BLOCK` | `1.0.0` | كتلة نصية ثابتة |
| `UI.HEADING` | `1.0.0` | عنوان ثابت |
| `UI.DIVIDER` | `1.0.0` | فاصل ثابت |

يجب احترام اختلاف سياسة الأطفال بين `UI.CONTAINER@1.0.0` و`UI.CONTAINER@1.1.0`. لا يجوز تغيير أي إصدار منشور؛ أي توسيع للعقد يتطلب إصداراً جديداً وسجل Registry جديداً.

### 2.4 حدود الموارد

حدود التنفيذ الحالية في `ui-component-runtime.js`:
- حجم JSON الأقصى: 65,536 بايت.
- عدد العقد الأقصى: 1,000.
- عمق التداخل الأقصى: 32.
- طول النص في العقدة: 10,000.
- إجمالي النص: 50,000.
- خصائص المكوّن: 16.
- حجم الخصائص: 4,096 بايت.

أي توسعة يجب أن تبقى ضمن الحدود الحالية أو تقترح تغييراً منفصلاً ومبرراً مع اختبارات حدود.

## 3. فصل القرار المعماري عن اعتماد العقود

اعتماد بناء المجموعة فوق `UI.TREE` لا يعني اعتماد تواقيع الرموز أو وسائطها أو أجسامها أو أنواعها أو آثارها الجانبية.

الحقول التالية تبقى غير محسومة حتى اعتماد عقد مستقل لكل رمز:
- موضع الاستخدام.
- عدد الوسائط وأنواعها ومخططها.
- السماح بكتلة `{...}` ومحتواها.
- نوع AST الدلالي.
- علاقة الرمز بغلاف الشجرة أو بعقدة المكوّن أو بعقدة النص.
- توليد معرّفات العقد.
- المخرجات والأخطاء.
- قواعد التداخل والأبوة وسياسة الأطفال.
- ربط المصدر بإصدارات Registry وملف القفل.

لا يجوز تمرير رمز إلى QIR لمجرد أن Parser يتعرف عليه.

## 4. خريطة التوافق الأولية — اقتراح غير معتمد

الجدول التالي يحدد نقاط التوافق المحتملة فقط؛ ولا يشكل قراراً دلالياً:

| الرمز | الوظيفة الدستورية | نقطة التوافق المحتملة | الحالة |
|---|---|---|---|
| `△ SCREEN` | إنشاء شاشة | قد يكون مسؤولاً عن إنشاء غلاف `QX.UI.TREE` أو سياق الشاشة | يحتاج اعتماد الشكل والوسائط والكتلة |
| `▱ PANEL` | إنشاء لوحة | قد يرتبط بـ`UI.CONTAINER` بعد تحديد خصائصه وعلاقته بالأبناء | يحتاج اعتماد العقد |
| `▰ BLOCK` | إنشاء كتلة واجهة | قد يرتبط بـ`UI.TEXT_BLOCK` أو نوع ثابت جديد | يحتاج تحديد هل هو نصي أم بنيوي |
| `◫ WINDOW` | إنشاء نافذة | لا يوجد حالياً نوع `UI.WINDOW` في السجل | غير مدعوم؛ يحتاج عقداً ومكوّناً مستقلاً |
| `⌑ BUTTON` | إنشاء زر | الزر التفاعلي يتطلب أحداثاً وصلاحيات وإتاحة واختبارات أمنية | محجوب عن الإصدار الأول؛ لا ينشأ زر وهمي أو تفاعلي |
| `▤ LAYOUT` | تحديد تخطيط العناصر | لا يوجد حالياً عقد تخطيط أو renderer مخصص له | غير مدعوم حتى اعتماد نموذج تخطيط محدود وآمن |

لا يجوز اعتماد أي من روابط التوافق المقترحة أعلاه دون مراجعة واعتماد صريح لعقد الرمز. ولا يجوز تمثيل WINDOW أو BUTTON أو LAYOUT باستخدام مكوّن آخر بطريقة تغيّر معناها الدستوري.

## 5. مراحل التنفيذ المقترحة

1. **اعتماد عقود الرموز:** حسم التوقيع والكتلة والسياق ونوع AST والعلاقة بشجرة UI لكل رمز.
2. **AST Adapter:** إضافة أنواع AST متخصصة فقط للرموز التي اكتملت عقودها.
3. **Semantic Analyzer:** التحقق من البنية والوسائط والأبوة وسياسة الأطفال ورفض غير المدعوم.
4. **UI Tree lowering:** تحويل البنية المعتمدة إلى غلاف `QX.UI.TREE` وعقد بيانات صحيحة؛ لا تنشأ تعليمات QIR تفاعلية.
5. **QIR:** استخدام `UI.TREE` القائم ما دام كافياً. لا إصدار QIR جديد إلا إذا ظهر احتياج بنيوي لا يغطيه QIR 1.4، ويُعرض ذلك كقرار مستقل.
6. **VM وWeb Backend:** الحفاظ على تحقق المضيف وملف القفل والعرض الآمن وحدود الموارد.
7. **الاختبارات:** Lexer/Parser، AST، القبول والرفض الدلالي، QIR، VM، Web Runtime، التوافق مع إصدارات Registry السابقة، واختبارات أمن وحدود.
8. **التوثيق والتثبيت:** تسجيل النتائج الفعلية وCommit مستقل لكل مرحلة ناجحة.

## 7. بوابة الانتقال إلى التنفيذ

قبل تعديل المصدر، يجب اعتماد التواقيع المقترحة للرموز التي ستدخل الإصدار الأول. تبقى بقية الرموز محجوبة برسالة دلالية صريحة إلى حين اكتمال عقودها. نجاح البناء أو وجود الرمز في Lexer/Parser لا يُعد دليلاً على دعم الرمز.
