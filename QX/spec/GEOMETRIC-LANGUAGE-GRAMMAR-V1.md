# قواعد التركيب الهندسي للغة QX
# QX Geometric Language Grammar — V1 Baseline

**الحالة | Status:** أساس تركيبي تنفيذي أولي — لا يغيّر اعتماد الرموز أو وظائفها.
**المرجع الأعلى | Canonical vocabulary:** `الدستور الهندسي للغة QX — QX Geometric Language Specification.md`
**النطاق | Scope:** Unicode tokenization, symbol invocation, expressions, statements, and structural blocks.

## 1. المبادئ الحاكمة

1. الأبجدية الأصلية هي الرموز الهندسية الـ72 المعتمدة في الدستور، لا الأسماء الإنجليزية.
2. كل رمز معتمد ينتج token واحداً من النوع `GEOMETRIC_SYMBOL`، ويحفظ الرمز الخام واسمه ومجموعته وموقعه في المصدر.
3. تطابق الرمز حرفي ودقيق. لا تُستبدل الرموز ولا تُطبع NFC بطريقة تغيّر تسلسل الرمز المركب.
4. الرموز المركبة الثلاثة `⛓️‍💥` و`⬢⃝` و`⬣⃝` تُلتقط كوحدات واحدة، مع أولوية أطول تطابق.
5. الأسماء الوظيفية واسم المجموعة metadata للتعريف والتحليل؛ لا تحل محل الرمز في المصدر.
6. هذه القواعد تحدد البنية النحوية العامة فقط. لا تمنح أي رمز وظيفة إضافية، ولا تعتبر مجرد نجاح التحليل إثباتاً لتنفيذ دلالته.

## 2. شكل الاستدعاء الأساسي

الصيغة العامة لكل رمز:

```qx
<GEOMETRIC_SYMBOL>(<arguments>)
```

أمثلة تركيبية:

```qx
⬡("application")
◉(users)
⊙(count, 10)
△("main-screen")
⧬(price * quantity)
⊢("Welcome")
```

- الأقواس `()` تحيط بقائمة الوسائط.
- الوسائط مفصولة بفاصلة `,`.
- يمكن أن تكون قائمة الوسائط فارغة.
- يمكن أن تحتوي الوسيطة على قيمة حرفية أو معرف أو تعبير أو قائمة أو استدعاء هندسي متداخل.
- لا يُفترض عدد الوسائط أو أنواعها من القواعد العامة؛ يحدد ذلك العقد الدلالي الخاص بكل رمز في مرحلة الدلالات.

## 3. الكتل البنيوية

يمكن أن يتبع استدعاء الرمز كتلة محاطة بقوسين معقوفين:

```qx
<GEOMETRIC_SYMBOL>(<arguments>) {
    <statement>
    <statement>
}
```

مثال بنيوي:

```qx
⟡(⟥(age, 18)) {
    ⊢("Allowed")
}
```

- `{` يبدأ كتلة و`}` ينهيها.
- الكتل قابلة للتداخل.
- كل تعليمة داخل الكتلة تنتهي بسطر جديد أو بحد الكتلة `}`.
- لا يجوز استخدام `}` دون كتلة مفتوحة.
- القواعد العامة تسمح بكتلة بعد أي رمز، لكن التحليل الدلالي اللاحق سيحدد الرموز التي تقبل كتلاً والوسائط المطلوبة لها، ويرفض التركيبات غير الصالحة.
- لا نعيد تعريف `⧯ FINISH` على أنه قوس إغلاق؛ يظل معناه المعتمد كما هو.

## 4. التعبيرات والوسائط

تدعم القاعدة التركيبية الحالية أنواع التعبيرات الموجودة في QX Core V1:
- أرقام صحيحة وعشرية.
- نصوص محاطة بعلامتي اقتباس مزدوجتين.
- القيم المنطقية وNULL وفق الكلمات الحالية في المحرك.
- المعرفات العربية أو اللاتينية وفق ضوابط Unicode الحالية.
- القوائم `[value, ...]`.
- التجميع `(expression)`.
- العمليات الحسابية والمقارنات والمنطقية وفق أسبقية QX Core V1 الحالية.
- الاستدعاء الهندسي المتداخل: `⊙(price, ⧬(base * rate))`.

تُكتب المقارنات الهندسية كاستدعاءات متداخلة للرموز المعتمدة، مثل `⟤(left, right)` للمساواة و`⟥(left, right)` للأكبر و`⟦(left, right)` للأصغر. لا تُستبدل هذه الرموز بعوامل تقليدية داخل الصياغة الهندسية لمجرد تشابه المعنى. العمليات الحسابية التي لا يقابلها رمز في الأبجدية تبقى وفق عوامل QX Core V1 الحالية إلى أن يصدر لها قرار لغوي مستقل.

## 5. حدود التعليمات والتعليقات

- تعليمة واحدة في كل سطر.
- لا تُستخدم الفاصلة المنقوطة لإنهاء التعليمة.
- التعليق أحادي السطر يبدأ بـ `//`.
- المسافات والأسطر الفارغة لا تغير معنى البرنامج خارج النصوص.
- تحتفظ مواقع المصدر بالأسطر والأعمدة والإزاحات لتشخيص الأخطاء.

## 6. تمثيل AST الأولي

ينتج استدعاء الرمز على مستوى التعليمة عقدة:

```text
GeometricStatement {
  symbol: functional-name,
  glyph: exact-source-glyph,
  group: canonical-symbol-group,
  args: Expression[],
  body: Statement[] | null,
  alternate: GeometricStatement | null,
  location: SourceLocation
}
```

وينتج الاستدعاء الهندسي داخل تعبير عقدة:

```text
GeometricCallExpression {
  symbol: functional-name,
  glyph: exact-source-glyph,
  group: canonical-symbol-group,
  args: Expression[],
  location: SourceLocation
}
```

يحافظ AST على الرمز الفعلي والمجموعة والوسائط والكتلة. وتُربط فروع `ELSE_IF` و`ELSE` بعقدة `IF` السابقة في حقل `alternate`. لا يحوّل الرمز إلى `DOMAIN.COMMAND` ولا إلى كلمة إنجليزية.

## 7. ما لا تدّعيه هذه المرحلة

هذه المرحلة تنفذ التقاط الرموز وبنية الاستدعاء والكتل العامة فقط. ولا تعني بعد:
- أن كل رمز من الـ72 يملك دلالة تنفيذية مكتملة.
- اعتماد عدد الوسائط أو أنواعها أو آثارها الجانبية لكل رمز.
- تحويل كل عقدة هندسية إلى QIR.
- دعم الرموز في VM أو Web Backend.
- أن جميع البرامج الهندسية قابلة للتنفيذ قبل اكتمال Semantic Analyzer وعقود QIR.

تُبنى العقود الدلالية لكل مجموعة بعد نجاح طبقة Lexer/Parser، مع الحفاظ على QX Core V1 الحالي والتوافق الخلفي.

## 8. معيار قبول هذه المرحلة

1. جرد المحرك يطابق الدستور: 12 مجموعة و72 رمزاً فريداً.
2. كل رمز مفرد أو مركب ينتج token واحداً ويحفظ تسلسله الخام.
3. الرموز المتجاورة لا تندمج ولا تتجزأ.
4. يمكن تحليل استدعاء كل رمز مع قائمة وسائط فارغة أو غير فارغة.
5. يمكن تحليل الاستدعاءات الهندسية المتداخلة.
6. يمكن تحليل الكتل المتداخلة وإظهار أخطاء الكتل غير المغلقة أو الإغلاق الزائد.
7. تبقى اختبارات الصياغة التقليدية الحالية ناجحة دون تغيير.
8. لا تتغير ملفات Mathematics أو رموزها أو روابطها.
