# البند التاسع — مخطط البناء

**الحالة:** الشريحة 9.1 مدمجة في `main` عبر PR #49؛ الشريحة 9.2 قيد التنفيذ عبر فرع مستقل؛ البند التاسع لم يُغلق.
**المرجع:** `QX/spec/ALI-QX-16-ITEM-IMPLEMENTATION-PLAN.md`، البند ٩.
**النطاق:** طبقة تخطيط مسبقة للتنفيذ في `engine/qx-core`، دون تعديل مولّد المشاريع أو منفّذ البناء أو مخطط المشروع القائم.

## 1. الهدف

إنشاء خريطة تتبّع تربط كل متطلب معتمد في المشروع بالمكوّنات المنطقية والملفات ومهام البناء التي تنتجها، مع تضمين سلسلة الاعتماديات اللازمة. يجب كشف النواقص والتعارضات قبل بدء الكتابة أو التنفيذ.

## 2. ما هو موجود مسبقاً ولا يعاد بناؤه

- `createBuildPlan` يربط المهام بالمدخلات والمخرجات والاعتماديات، ويرفض المهام المكررة والاعتماديات المفقودة والدورات وتعارض منتجي المخرجات والمدخلات غير المعلنة.
- `assertBuildPlanForProject` يربط المخطط بالموافقة وبصمة نسخة المشروع الدقيقة.
- `requirement-coverage.js` يربط المتطلبات بمعايير القبول والاختبارات وأدلة الملفات بعد إنتاج تقارير الاختبار والتسليم، كما يتحقق من اكتمال تعريفات التغطية قبل الكتابة.
- هذه الوظائف لا توفر حتى الآن خريطة مسبقة موحدة تربط كل متطلب بمكوّن وملف ومهمة وسلسلة اعتمادياتها.

## 3. الشريحة 9.1 — خريطة تتبّع المتطلبات إلى البناء

تضيف `createRequirementBuildMap(project, { expectedProjectDigest, buildPlan, mappings, fileBindings })` و`assertRequirementBuildMapForProject(project, buildPlan, map)` في `engine/qx-core/src/requirement-build-map.js`.

### مدخلات الخريطة

- `fileBindings`: سجلات يقدّمها المضيف تربط مسار ملف نسبي آمن بمعرّف artifact ومهمة الإنتاج ومعرّفات المكوّنات المرتبطة بذلك الملف.
- `mappings`: سجل واحد لكل متطلب من `requirements` و`dataRequirements` و`integrationRequirements`، يحدد الفئة والفهرس ومعرّفات المكوّنات ومسارات الملفات المرتبطة.

### المخرجات

- هوية المشروع ومراجع المراجعة والبصمة المعتمدة.
- بصمة مخطط البناء المستخدم.
- روابط ملفات/artifacts/مهام الإنتاج التي قدمها المضيف.
- سجل لكل متطلب يتضمن نص المتطلب وفئته ومعرّفاته ومكوّناته وملفاته، إضافة إلى المهام المنتجة وسلسلة اعتمادياتها السابقة.
- بصمة حتمية وتجميد عميق للخريطة.

### التحقق وحدود الثقة

1. لا تُقبل إلا نسخة مشروع معتمدة ببصمتها الدقيقة، ومخطط بناء صالح لنفس النسخة.
2. يجب تمثيل كل متطلب وظيفي وبياني وتكاملي مرة واحدة بالضبط؛ لا متطلبات مجهولة أو مكررة أو ناقصة.
3. يجب أن يكون كل ملف مساراً نسبياً آمناً، وأن يرتبط artifact بمهمة تنتجه فعلاً في المخطط.
4. يُرفض تكرار مسار ملف أو ربط artifact واحد بأكثر من ملف.
5. يجب أن تتطابق المكوّنات المذكورة للمتطلب مع المكوّنات المرتبطة بملف واحد على الأقل من ملفاته.
6. تُشتق مهام كل متطلب من مهام إنتاج ملفاته، وتُدرج جميع الاعتماديات السابقة وفق ترتيب المخطط؛ لا يقبل المستخدم قائمة اعتماديات غير متحققة.
7. إعادة التحقق تعيد بناء الخريطة وتطابقها، وتكشف أي تعديل أو قدم في بصمات المشروع أو المخطط أو الخريطة.
8. معرّفات المكوّنات روابط وصفية يقدّمها المضيف؛ هذه الشريحة لا تحلّ المكوّنات ولا تفعّلها ولا تتجاوز تحقق UI lock أو المولّد.
9. الخريطة للقراءة والتخطيط فقط؛ لا تكتب ملفات ولا تشغّل مهاماً ولا تمنح موافقة أو صلاحية بناء.

### معايير قبول 9.1

- خريطة كاملة لكل فئات المتطلبات، مع ملفات ومكوّنات ومهام واعتماديات متحققة.
- رفض المتطلبات الناقصة والمكررة والمجهولة.
- رفض المسارات غير الآمنة وملكية الملفات المتعارضة وارتباطات artifacts غير الصحيحة.
- إثبات تضمين سلسلة الاعتماديات السابقة لكل مهمة إنتاج.
- رفض الخريطة المعدلة أو المرتبطة بمشروع/مخطط قديم.
- حتمية المخرجات وتجميدها بعمق.
- اختبارات مستقلة للحالات الصحيحة والحدية والفشل.
- عدم تغيير سلوك `createBuildPlan` أو `runProjectBuildWorkflow` وعدم تنفيذ أي كتابة أو بناء.

**حالة التنفيذ:** أضيفت الشريحة 9.1 والاختبارات وتصدير API على الفرع `feat/item-9-1-requirement-build-map`. لا تعتبر مكتملة قبل نجاح فحوص CI ومراجعة diff ودمجها بموافقة منفصلة.


## 4. الشريحة 9.2 — مخطط البناء الموحد

تضيف `createBuildBlueprint(project, { expectedProjectDigest, buildPlan, requirementBuildMap })` و`assertBuildBlueprintForProject(project, buildPlan, requirementBuildMap, blueprint)` في `engine/qx-core/src/build-blueprint.js`.

### الهدف والمخرجات

دمج مراجع خطة البناء وخريطة تتبّع المتطلبات في تمثيل واحد ثابت يمكن مراجعته والتحقق منه قبل الانتقال إلى التوليد. يتضمن المخطط:

- هوية المشروع ومراجع المراجعة والبصمة المعتمدة.
- بصمة `buildPlan` وبصمة `requirementBuildMap` اللتين بُني عليهما المخطط.
- ترتيب المهام، واعتماديات كل مهمة ومدخلاتها ومخرجاتها.
- ملفات المشروع المربوطة بمخرجاتها ومهام إنتاجها ومكوّناتها.
- روابط كل متطلب وظيفي أو بياني أو تكاملي إلى ملفاته ومكوّناته ومهامه.
- قائمة المتطلبات الخارجية وترتيب التنفيذ الحتمي، وبصمة للمخطط الموحد.

### التحقق وحدود الثقة

1. لا يُنشأ المخطط إلا لمشروع معتمد وخطة بناء وخريطة متطلبات صالحتين ومتطابقتين معه.
2. تُعاد الاستفادة من مدققات الخطة والخريطة؛ لا يعيد هذا API تفسير الاعتماديات أو قبول روابط يقدمها المستدعي خارج الخريطة المتحققة.
3. تُشتق روابط الملفات والمتطلبات على مستوى المهمة من الخريطة، ولا تُقبل كمدخلات مستقلة قابلة للتلاعب.
4. إعادة التحقق ترفض البيانات غير الصالحة أو ذات accessors، وتعيد بناء المخطط من المصادر الموثوقة وتقارن المحتوى والبصمة.
5. المخرجات حتمية ومجمّدة بعمق، وترتبط ببصمات المشروع والخطة والخريطة الدقيقة.
6. المخطط للقراءة والتخطيط فقط؛ لا يكتب ملفات، ولا يشغّل مهاماً، ولا يعدّل المشروع أو موافقته، ولا يمنح صلاحية التوليد أو البناء.
7. لا يتغير سلوك `createBuildPlan` أو `createRequirementBuildMap` أو `runProjectBuildWorkflow`، ولا يبدأ ربط المخطط بمولّد المشاريع ضمن هذه الشريحة.

### معايير قبول 9.2

- مخطط موحد يتضمن كل المهام والملفات وروابط المتطلبات والاعتماديات المشتقة.
- كل مهمة تحتفظ بترتيبها ومدخلاتها ومخرجاتها واعتمادياتها من خطة البناء المتحققة.
- كل ملف ومتطلب مرتبط بمراجع المصدر الصحيحة، مع إمكانية تتبع المتطلب إلى مهمة الإنتاج وسلسلة اعتمادياتها.
- رفض المشروع أو الخطة أو خريطة المتطلبات القديمة أو غير المتطابقة.
- رفض العبث بالمخطط أو إدخال بيانات ذات accessors، والتحقق من البصمة وإعادة البناء.
- حتمية المخرجات والتجميد العميق.
- اختبارات مستقلة للحالات الصحيحة وإعادة الترتيب والتلاعب والمدخلات القديمة والحدية.
- عدم تنفيذ كتابة أو توليد أو تشغيل مهام، وعدم تغيير سلوك واجهات البناء القائمة.

**حالة التنفيذ:** أضيفت الشريحة 9.2 على الفرع `feat/item-9-2-build-blueprint`، وتشمل API والاختبارات وتصدير الواجهة. لا تعتبر مكتملة قبل نجاح فحوص CI ومراجعة diff ودمجها بموافقة منفصلة.
