# عقود مجموعة DATA — مسودة المراجعة الأولى

> الحالة: **عقود DATA مثبتة؛ تنفيذ ADD وREMOVE اجتاز اختبارات النواة والويب على PR #6، والدمج في main لم يحدث بعد**  
> الأساس البرمجي: `main` بعد المرحلة الخامسة، مع تنفيذ مقترح على `feature/phase6-data-ops`.  
> مواصفة QIR: QIR V1.0 محفوظة، وامتداد DATA متوافق 1.1 موثق في `QIR-DATA-LIST-EXTENSION-1.1.md`.  
> طلب المراجعة: https://github.com/alisrm73/ALI-QX/pull/6.

## 1. قرار النطاق

تغطي هذه المراجعة أربع عمليات موجودة في المسار الدلالي أو التنفيذي:

- `DATA.CREATE`
- `DATA.SET`
- `DATA.SET_GLOBAL`
- `DATA.COUNT`

تغطي هذه الوثيقة عقود `DATA.ADD` و`DATA.REMOVE` المنفذة في فرع المرحلة السادسة. أما `DATA.GET` فيبقى خارج DATA V1 حالياً لعدم وجود نوع تعبيري آمن يمثّل قيمة عنصر قائمة قد تكون مختلطة الأنواع؛ وتفاصيل ذلك موثقة في القسم 10.

## 2. قواعد مشتركة

- المعرّف الداخلي ثابت ولا يتغير باختلاف اللغة.
- لكل عملية اسم إنجليزي واحد واسم عربي واحد، وفق سجل الأسماء الحالي.
- أنواع القيم المعروفة: `NUM`, `TXT`, `BOOL`, `LIST`. القيمة `NULL` ليست نوعاً أساسياً لاستنتاج نوع متغير.
- لا توجد تحويلات ضمنية بين الأنواع.
- المعرّفات تخضع لقواعد QX الحالية وتطبيع Unicode NFC.
- أخطاء النوع أو الاسم أو النطاق تُكتشف دلالياً قبل خفض البرنامج إلى QIR.
- لا تمنح هذه الوثيقة أي عملية صلاحية قراءة ملفات المضيف أو الشبكة أو تنفيذ شيفرة خارجية.
- `DATA.SET_GLOBAL` صالح داخل الدوال فقط؛ الاستخدام على مستوى الوحدة مرفوض دلالياً.
- الإصدار المقترح للعقود في هذه المسودة هو `0.1.0-draft`، وليس إصدار مكتبة منشوراً.

## 3. العقد: DATA.CREATE

| الحقل | العقد المقترح |
|---|---|
| المعرّف | `DATA.CREATE` |

| الإصدار | `0.1.0-draft` |

| الصيغة الحالية | `DATA.CREATE(identifier, initialValue)` |
| المدخل الأول | `identifier`: معرّف متغير، إلزامي |
| المدخل الثاني | `initialValue`: تعبير ينتج `NUM` أو `TXT` أو `BOOL` أو `LIST`، إلزامي |

| الأثر | إنشاء متغير وتهيئته مرة واحدة |
| تحديد النوع | يستنتج من نوع التعبير الابتدائي |
| NULL | يرفض إذا كان التعبير الابتدائي `NULL` مباشرةً |
| النطاق | متغير محلي داخل الدالة، أو عام على مستوى الوحدة |
| التكرار | يرفض تكرار الاسم في النطاق نفسه |

| الصلاحيات | لا يحتاج صلاحيات خارجية |
| الحتمية | حتمي لنفس المصدر والسياق |
| أخطاء قائمة | `QX3017` وسيط غير صالح؛ `QX3018` تعذر استنتاج النوع من NULL؛ `QX3001` تكرار تعريف؛ `QX3036` تعذر استنتاج نوع فريد |
| الاختبارات المطلوبة | كل نوع مدعوم؛ قائمة فارغة ومختلطة؛ NULL المباشر؛ التكرار؛ النطاق؛ موضع الخطأ؛ توافق QIR وVM وWeb Runtime |

**حدود العقد:** لا تحدد هذه العملية قيمة افتراضية عند حذف المدخل الثاني؛ المدخلان إلزاميان. ولا تسمح بإعادة تعريف المتغير نفسه داخل النطاق نفسه.

**حدود العقد:** لا تقوم العملية بإحصاء عناصر متداخلة أو جمع قيمها أو إزالة التكرارات؛ هي تعيد عدد العناصر المباشرة في القائمة فقط.

## 7. ملخص التوافق الحالي

| العملية | تحليل دلالي | خفض QIR | VM | Web Runtime | مفعّلة في Registry |
|---|---|---|---|---|---|
| `DATA.CREATE` | معالجة خاصة | DECLARE/STORE | عبر تعليمات QIR | عبر تعليمات QIR | لا |
| `DATA.SET` | معالجة خاصة | STORE_LOCAL/STORE_GLOBAL بحسب النطاق | عبر تعليمات QIR | عبر تعليمات QIR | لا |
| `DATA.SET_GLOBAL` | معالجة خاصة | STORE_GLOBAL | عبر تعليمات QIR | عبر تعليمات QIR | لا |
| `DATA.COUNT` | عقد صريح | COMMAND_CALL | تنفيذ مباشر | تنفيذ مباشر | نعم |

هذا الجدول يصف مسار التنفيذ الحالي ولا يغيّر حقيقة أن CREATE/SET/SET_GLOBAL لها معالجة خاصة وليست أوامر مفعلة في Registry.

## 8. قرارات العقود

1. **DATA.SET_GLOBAL:** يقتصر على الدوال فقط؛ التنفيذ البرمجي لم يبدأ بعد.
2. **DATA.ADD:** إضافة قيمة واحدة إلى نهاية القائمة وإرجاع قائمة جديدة.
3. **DATA.REMOVE:** إزالة عنصر واحد باستخدام فهرس صفري البداية وإرجاع قائمة جديدة.
4. **DATA.GET:** مؤجل من DATA V1؛ لا يُفعّل قبل وجود تصميم معتمد لنوع قيمة العنصر في نظام الأنواع وQIR.
5. **الاسم العربي:** تبقى الأسماء العربية الحالية في Registry كما هي في هذه المرحلة.

## 9. ما لم يتغير

- لم تتغير ملفات المصدر أو الاختبارات.
- لم يتغير سجل الأوامر أو حالة التفعيل.
- لم تتغير مواصفة QIR V1 أو VM أو Web Backend.
- لم تُفعّل عمليات GET/ADD/REMOVE؛ أضيفت عقود ADD وREMOVE إلى هذه المسودة فقط، وبقي GET مؤجلاً.
- هذه الوثيقة مسودة مستقلة للمراجعة ولا تمثل اعتماداً نهائياً للعقود.

**بوابة الانتقال:** بعد اعتماد هذه العقود والقرارات المفتوحة، يمكن تحويلها إلى مواصفة DATA V1 نهائية، ثم تحديد تنفيذ مستقل واختبارات قبول قبل أي تغيير برمجي.


## 10. مراجعة الأوامر المعلقة: DATA.GET وDATA.ADD وDATA.REMOVE

### 10.1 ما تثبته الشيفرة الحالية

| البند | DATA.GET | DATA.ADD | DATA.REMOVE |
|---|---|---|---|
| الاسم الإنجليزي في Registry | موجود | موجود | موجود |
| الاسم العربي في Registry | `جلب` | `إضافة` | `إزالة` |
| توقيع في Registry | لا يوجد | لا يوجد | لا يوجد |
| حالة التوقيع | `pending` | `pending` | `pending` |
| التفعيل | معطل | معطل | معطل |
| عقد دلالي خاص | لا | لا | لا |
| خفض QIR معتمد | لا | لا | لا |
| دعم VM / Web Runtime | لا | لا | لا |

المصدر: `engine/qx-core/src/command-registry.js` على `main`. يضع السجل `signature: null` لهذه الأوامر، ويجعلها غير مفعّلة ما لم تكن ضمن الأوامر ذات العقود المعتمدة.

### 10.2 سلوك الرفض الحالي

- عند تحليل استدعاء هذه الأوامر كتعليمة، لا يجد المحلل الدلالي عقداً معتمداً لها، ويصدر الخطأ `QX3040`.
- لا يملك مولّد QIR مسارات خفض لهذه العمليات؛ المسارات المعتمدة لعمليات DATA الحالية تقتصر على CREATE وSET وSET_GLOBAL وCOUNT.
- لا تقبل VM وWeb Runtime أوامر `COMMAND_CALL` إلا `DATA.COUNT` في QIR V1.
- لذلك وجود الاسم في Registry لا يعني أن العملية قابلة للاستدعاء أو التنفيذ.

### 10.3 المسائل التي يجب حسمها قبل صياغة العقود

**DATA.GET — قرار التأجيل:**
- لا يدخل `DATA.GET` ضمن DATA V1 ولا يُفعّل في هذه المرحلة.
- السبب: القوائم الحالية تقبل عناصر مختلطة الأنواع، بينما نظام الأنواع لا يعرّف `ANY` أو اتحاد الأنواع أو نوع عنصر قائمة عامّاً. لذلك لا يمكن إعطاء ناتج GET نوعاً ثابتاً آمناً يمكن التحقق منه دلالياً وتمثيله في QIR V1.
- يعاد فتح القرار فقط بعد اعتماد امتداد مستقل لنظام الأنواع وQIR يحدد نوع النتيجة وسلوك الفهرس خارج الحدود.

**DATA.ADD — العقد المقترح:**
- الصيغة: `DATA.ADD(listExpression, valueExpression)`، بوسيطين إلزاميين.
- يضيف القيمة في نهاية القائمة فقط؛ لا يوجد إدراج في موضع مخصص ضمن V1.
- يقبل `NUM` أو `TXT` أو `BOOL` أو `LIST` أو `NULL` كقيمة مضافة، مع الحفاظ على ترتيب العناصر.
- يعيد `LIST` جديدة ولا يغيّر القائمة الأصلية. تُنسخ القيم المتداخلة نسخاً عميقاً وفق نموذج القيم المعتمد.
- إذا تجاوز طول النتيجة حد القائمة المعتمد (`maxListLength`)، يفشل التنفيذ بخطأ موارد واضح.

**DATA.REMOVE — العقد المقترح:**
- الصيغة: `DATA.REMOVE(listExpression, indexExpression)`، بوسيطين إلزاميين.
- الفهرس `NUM` صحيح غير سالب ويبدأ من الصفر.
- يزيل العنصر الموجود عند الفهرس المحدد فقط، حتى مع وجود قيم مكررة؛ لا تستخدم الإزالة بالقيمة في V1.
- يعيد `LIST` جديدة مع الحفاظ على ترتيب بقية العناصر، ولا يغيّر القائمة الأصلية.
- الفهرس السالب أو غير الصحيح أو الخارج عن حدود القائمة ينتج خطأ وقت التنفيذ، ولا يعيد القائمة دون تغيير.

### 10.4 القرارات المشتركة المحسومة

تُطبق القواعد التالية على عمليات القوائم:
- **قرار معتمد:** القوائم تُعامل كقيم غير قابلة للتعديل مباشرة؛ أي عملية تغيّر محتوى قائمة يجب أن تنتج نسخة جديدة بدلاً من تعديل القائمة الأصلية.
- **قرار معتمد:** `DATA.ADD` و`DATA.REMOVE` عمليتان تعبيريّتان تعيدان قائمة جديدة من النوع `LIST`، ويمكن إسناد النتيجة عبر `DATA.CREATE` أو `DATA.SET`.
- **قرار معتمد:** `DATA.ADD` تضيف إلى نهاية القائمة فقط، بوسيطين: القائمة والقيمة.
- **قرار معتمد:** `DATA.REMOVE` تزيل بالفهرس الصفري البداية، بوسيطين: القائمة والفهرس؛ تزيل عنصراً واحداً فقط.
- **قرار معتمد:** الفهرس غير الصحيح أو السالب أو خارج الحدود خطأ وقت تنفيذ، ولا يغيّر المصدر.
- **قرار معتمد:** `DATA.GET` مؤجل من V1 لغياب نوع `ANY`/اتحاد الأنواع الذي يضمن سلامة قيمة عنصر قائمة مختلطة.
- القيم القائمة المتداخلة تُنسخ بعمق عند إنتاج قائمة جديدة.
- الفهارس في `DATA.REMOVE` تبدأ من الصفر، ويجب أن تكون أعداداً صحيحة ضمن حدود القائمة.
- تُحصر المدخلات والمخرجات والأخطاء لكل من ADD وREMOVE في القسم 10.8–10.9 أدناه.
- لا تعتمد GET قبل حل تمثيل نوع عنصر القائمة.
- يجب أن يتطابق السلوك بين Semantic Analyzer وQIR وVM وWeb Runtime.
- تثبت اختبارات القبول هذا التطابق قبل تفعيل الأمرين.

### 10.5 حدود هذه المراجعة

- لم تُعتمد توقيعات Registry أو مسارات تنفيذ بعد. دلالات ADD وREMOVE مثبتة كقرارات تصميم في هذه المسودة؛ GET مؤجل.
- لم تُفعّل هذه الأوامر ولم تُضف لها مسارات تنفيذ.
- لم تتغير ملفات المصدر أو الاختبارات أو Registry أو مواصفة QIR V1.
- هذه المسودة توثق قرارات التصميم النهائية المقترحة لمجموعة DATA، لكنها لا تمنح إذناً لتعديل المصدر أو تفعيل الأوامر.

**بوابة التنفيذ:** قرارات تصميم ADD وREMOVE محسومة في هذه المسودة. يبقى GET خارج V1. قبل التنفيذ، يلزم إعداد امتداد QIR مستقل لأن QIR V1 لا يعرّف حالياً عمليات قائمة تعبيرية، ثم إضافة العقود إلى Registry والمحلل الدلالي والـ VM والـ Web Runtime واختبارات القبول.


### 10.6 قرار نموذج القوائم

**الحالة: معتمد ومنفذ في فرع المرحلة السادسة؛ بانتظار دمج PR #6.**

- لا تعدّل عمليات DATA محتوى قائمة موجودة في مكانها.
- أي عملية تغيّر محتوى قائمة تنتج قائمة جديدة، مع بقاء القائمة الأصلية كما هي.
- يجب أن تحافظ النسخة الجديدة على ترتيب العناصر ما لم ينص عقد عملية محددة على غير ذلك.
- تفاصيل الصيغة والنتيجة مثبتة في عقدي ADD وREMOVE في القسمين 10.8 و10.9.
- لا يغيّر هذا القرار سلوك VM أو Web Runtime حالياً، ولا يضيف دعماً لتعديل القوائم أو أوامر جديدة.


### 10.7 قرار نتيجة DATA.ADD وDATA.REMOVE

**الحالة: معتمد ومنفذ في فرع المرحلة السادسة؛ بانتظار دمج PR #6.**

- `DATA.ADD` و`DATA.REMOVE` تعيدان قيمة تعبيرية من النوع `LIST` تمثل قائمة جديدة.
- يمكن تمرير النتيجة إلى تعبير آخر أو إسنادها إلى متغير باستخدام `DATA.CREATE` أو `DATA.SET`.
- لا تتغير القائمة الأصلية؛ وتُحافظ القائمة الجديدة على ترتيب العناصر وفق القاعدة العامة، ما لم يُعتمد خلاف ذلك في عقد العملية.
- صيغة الوسائط ودلالات الإضافة والإزالة موضحة في القسمين 10.8 و10.9.
- لا يعني اعتماد التصميم تفعيل الأمرين أو إضافة توقيع Registry أو تعديل QIR V1 أو تنفيذ VM/Web Runtime. تتطلب هذه الأعمال امتداد QIR مستقلّاً واختبارات قبول.


### 10.8 عقد DATA.ADD — إضافة إلى نهاية القائمة

| الحقل | القرار المعتمد في المسودة |
|---|---|
| الصيغة | `DATA.ADD(listExpression, valueExpression)` |
| عدد الوسائط | وسيطان إلزاميان |
| الوسيط الأول | تعبير من النوع `LIST` |
| الوسيط الثاني | قيمة من الأنواع `NUM`, `TXT`, `BOOL`, `LIST`, أو `NULL` |
| السلوك | إضافة القيمة كعنصر أخير؛ لا إدراج حسب فهرس في V1 |
| النتيجة | قائمة جديدة من النوع `LIST` |
| الأثر على المصدر | لا تعديل للقائمة الأصلية |
| النسخ | نسخ عميق للقيم القائمة المتداخلة، بما يمنع مشاركة بنية قابلة للتغيير بين النتيجة والمصدر |
| حد الموارد | احترام `maxListLength`; تجاوز الحد خطأ وقت تنفيذ |
| الحتمية | حتمي ويحافظ على ترتيب العناصر السابقة |
| الصلاحيات | لا صلاحيات مضيف أو شبكة أو ملفات |

### 10.9 عقد DATA.REMOVE — إزالة عنصر بالفهرس

| الحقل | القرار المعتمد في المسودة |
|---|---|
| الصيغة | `DATA.REMOVE(listExpression, indexExpression)` |
| عدد الوسائط | وسيطان إلزاميان |
| الوسيط الأول | تعبير من النوع `LIST` |
| الوسيط الثاني | `NUM` صحيح غير سالب، يبدأ العد من صفر |
| السلوك | إزالة عنصر واحد عند الفهرس المحدد |
| التكرارات | لا تؤثر؛ التحديد بالفهرس لا بالقيمة |
| النتيجة | قائمة جديدة من النوع `LIST` |
| الأثر على المصدر | لا تعديل للقائمة الأصلية |
| الفهرس غير الصحيح/السالب/خارج الحدود | خطأ وقت تنفيذ محدد، دون تغيير المصدر |
| ترتيب العناصر | الحفاظ على الترتيب النسبي للعناصر المتبقية |
| الصلاحيات | لا صلاحيات مضيف أو شبكة أو ملفات |

### 10.10 قرار DATA.GET — مؤجل من V1

لا نعتمد `DATA.GET` في DATA V1 حالياً. القوائم تسمح بعناصر مختلطة، ولا يدعم نظام الأنواع الحالي نوعاً عاماً مثل `ANY` أو اتحاد أنواع لعناصر القائمة. إرجاع عنصر قد يكون من أنواع مختلفة دون عقد نوعي صريح سيضعف التحقق الساكن ويخلق اختلافاً محتملاً بين المحلل وQIR وبيئات التنفيذ. يبقى الاسم في Registry معطلاً وبتوقيع `pending`. يعاد تصميمه فقط ضمن امتداد مستقل لنظام الأنواع وQIR، ولا نضيف تحويلاً ضمنياً أو قيمة بديلة عند غياب الفهرس.

### 10.11 متطلبات ما قبل التنفيذ

1. إعداد مواصفة امتداد مستقلة لـ QIR لإضافة عمليات القوائم التعبيرية؛ لا نغيّر QIR V1 المعتمد ضمن هذه المسودة.
2. تحديد تعليمات QIR أو lowering صريح لـ ADD وREMOVE، والتحقق من سلامة الأنواع والوسائط.
3. تحديث Registry وSemantic Analyzer فقط بعد اعتماد امتداد QIR.
4. تنفيذ السلوك نفسه في VM وWeb Runtime مع نسخ القيم واحترام حدود الموارد.
5. إضافة اختبارات: الإضافة إلى قائمة فارغة وغير فارغة؛ كل أنواع العناصر؛ عدم تغير الأصل؛ النسخ المتداخل؛ حد القائمة؛ إزالة أول/وسط/آخر عنصر؛ قائمة بعنصر واحد؛ فهرس سالب/كسري/مساوٍ للطول؛ تطابق VM وWeb Runtime.
6. تبقى `DATA.GET` معطلة ولا تدخل اختبارات التفعيل حتى اعتماد امتداد الأنواع.

**حالة التنفيذ والتحقق:** ADD وREMOVE منفذان في الفرع على مستوى Registry وSemantic Analyzer وQIR 1.1 وVM وWeb Runtime. اجتازت مجموعة النواة 109/109 اختبارات، واجتاز فحص Chromium الخاص بالويب. QIR V1.0 لم تتغير. `DATA.GET` مؤجل ومعطل. الدمج في main لم يحدث بعد.
