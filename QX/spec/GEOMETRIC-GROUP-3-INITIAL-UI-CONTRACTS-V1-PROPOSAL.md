# المجموعة الثالثة — مقترح عقود الإصدار الأول

**الحالة:** مقترح للمراجعة والاعتماد؛ ليس عقداً دستورياً نافذاً.  
**الاتجاه المعماري المعتمد:** طبقة هندسية فوق `UI.TREE`.  
**الرموز المقترحة للإصدار الأول:** SCREEN, PANEL, BLOCK.  
**الرموز المؤجلة:** WINDOW, BUTTON, LAYOUT.

## 1. هدف المقترح

توفير صيغة QX موجزة لإنشاء شجرة عرض ثابتة، مع إعادة استخدام جسر QIR 1.4 وسجل المكونات المضيف الحالي. لا يضيف المقترح أنواع مكونات أو Renderer أو صلاحيات جديدة.

## 2. التواقيع المقترحة

### 2.1 SCREEN

**الصيغة:**
```qx
△() {
  ...
}
```

- الموضع: تعليمة على مستوى الوحدة فقط.
- الوسائط: لا شيء.
- الكتلة: مطلوبة.
- العدد: شاشة واحدة كحد أقصى في الوحدة.
- المحتوى المباشر المسموح: PANEL أو BLOCK.
- الأثر: إنشاء غلاف `QX.UI.TREE` ووضع عقد الكتلة داخله.
- لا ينتج SCREEN عقدة component، لأن غلاف الشجرة ليس مكوّناً قابلاً للعرض ولا يحمل id.

### 2.2 PANEL

**الصيغة:**
```qx
▱(content) {
  ...
}
```

- الموضع: داخل SCREEN أو PANEL فقط.
- الوسائط: Identifier واحد إلزامي يمثل id ثابتاً للعقدة.
- الكتلة: مطلوبة.
- المحتوى المباشر المسموح: PANEL أو BLOCK.
- الأثر: إنشاء عقدة `component` من النوع `UI.CONTAINER@1.0.0`، مع `props: {}` وأبناء الكتلة.
- يجب أن تكون قيمة id فريدة في الشجرة كلها. يحول اسم Identifier إلى نص id حرفي؛ لا يجري حلّه كمتغير QX.

### 2.3 BLOCK

**الصيغة:**
```qx
▰(title, "Literal text")
```

- الموضع: داخل SCREEN أو PANEL فقط.
- الوسائط: Identifier واحد إلزامي للـid، ثم تعبير TXT واحد إلزامي للمحتوى.
- الكتلة: ممنوعة.
- الأثر: إنشاء عقدة `component` من النوع `UI.TEXT_BLOCK@1.0.0`، مع `props: {}` وعقدة نص واحدة في children.
- يجب أن يكون التعبير الثاني من النوع TXT وقت التحليل الدلالي.
- اسم Identifier الأول يتحول إلى نص id حرفي ولا يجري حلّه كمتغير QX.

## 3. مثال مقترح

```qx
△() {
  ▱(main) {
    ▰(title, "Welcome to QX")
    ▱(details) {
      ▰(description, "A static and validated interface")
    }
  }
}
```

الناتج المفاهيمي هو غلاف `QX.UI.TREE@1.0` يحتوي:
- `UI.CONTAINER@1.0.0` بمعرّف `main`.
- داخله `UI.TEXT_BLOCK@1.0.0` بمعرّف `title`.
- و`UI.CONTAINER@1.0.0` متداخل بمعرّف `details` يحتوي `UI.TEXT_BLOCK@1.0.0` بمعرّف `description`.

يجب أن يبقى إصدار كل مكوّن مثبتاً من خلال `qx.ui-lock.json` وسجل المضيف، ولا يختار مصدر QX إصدار المكوّن.

## 4. قواعد التحقق المقترحة

1. وجود أكثر من SCREEN في الوحدة خطأ دلالي.
2. غياب SCREEN مع وجود PANEL أو BLOCK خطأ دلالي.
3. SCREEN لا يسمح بالتداخل داخل SCREEN أو PANEL.
4. PANEL وBLOCK لا يسمحان خارج SCREEN أو PANEL.
5. PANEL لا يسمح بأكثر من وسيط واحد أو أقل منه.
6. BLOCK يتطلب وسيطين بالضبط؛ الأول Identifier والثاني TXT.
7. تكرار أي id ضمن الشجرة خطأ قبل خفض QIR.
8. BLOCK لا يقبل كتلة.
9. PANEL وSCREEN يتطلبان كتلة.
10. يجب رفض أي طفل غير مسموح به قبل توليد QIR.
11. لا يسمح بتوليد HTML أو JavaScript أو CSS أو event handlers من هذه الرموز.
12. لا يحدث أي عرض جزئي عند فشل التحقق من الشجرة أو القفل أو سجل المضيف.

## 5. حدود التوافق

- `SCREEN` يحول البنية إلى غلاف `QX.UI.TREE` فقط.
- `PANEL` يعاد استخدامه كـ`UI.CONTAINER@1.0.0`؛ لا يتغير عقد المكوّن ولا سجل المضيف.
- `BLOCK` يعاد استخدامه كـ`UI.TEXT_BLOCK@1.0.0`؛ لا يتغير عقد المكوّن ولا سجل المضيف.
- يبقى جسر `UI.TREE(TXT)` الحالي هو مسار QIR. لا يتطلب المقترح opcode جديداً أو إصدار QIR جديداً.
- لا تضاف خصائص أو تنسيقات أو تفاعلات.
- تبقى `WINDOW` و`BUTTON` و`LAYOUT` محجوبة، ولا تُحوّل إلى رموز بديلة.

## 6. ما يحتاج اعتماداً صريحاً

هذا المقترح يطلب اعتماد النقاط التالية قبل التنفيذ:
- SCREEN بلا وسائط وبكتلة إلزامية وعلى مستوى الوحدة مرة واحدة كحد أقصى.
- PANEL بوسيط Identifier واحد يمثل id وبكتلة إلزامية.
- BLOCK بوسيطين: Identifier للـid وتعبير TXT للمحتوى، ومن دون كتلة.
- السماح بـPANEL وBLOCK داخل SCREEN وPANEL فقط.
- استخدام أسماء Identifier كمعرّفات حرفية لعقد UI، لا كمتغيرات QX.

إلى حين اعتماد هذه النقاط، تظل الرموز الثلاثة محجوبة دلالياً ولا يتم خفضها إلى QIR.
