# INTEGRATION — عقد طبقة الموصلات الآمنة (مسودة تنفيذية)

> الحالة الحالية على `main` عند commit `13661dbe05092819bb2b44fce7372ff43adb2db1`: طبقة broker معزولة، وربط `INTEGRATION.REQUEST` باللغة وQIR 1.3 ومسار VM غير المتزامن منفذ. لا يوجد اتصال شبكي افتراضي أو موصل إنتاجي مضمّن.

## 1. الحدود الأمنية

- لا يملك مصدر QX أو QIR أو VM وصولاً مباشراً إلى الشبكة أو الملفات أو متغيرات البيئة أو مخزن الأسرار.
- لا تُقبل إلا معرفات موصلات وعمليات مسجلة مسبقاً من المضيف؛ لا تقبل الطبقة URL أو عنوان IP أو اسم مضيف كوجهة.
- المنع هو الوضع الافتراضي: كل عملية تتطلب منحة صريحة لكل الصلاحيات التي تعلنها.
- يبقى تنفيذ الموصل داخل Adapter يثق به المضيف؛ وتُحفظ بيانات الاعتماد داخل إغلاق adapter أو مزود أسرار موثوق، ولا تمر عبر وسيطات QX أو سجلاته.
- لا يثبت تسجيل الموصل أو منحه الصلاحية أن المستخدم وافق على موصل بعينه؛ يجب أن تأتي المنح من واجهة موافقة موثوقة خارج البرنامج.
- لا توجد موصلات حقيقية أو أسرار أو عناوين خدمات في هذه الدفعة؛ الاختبارات تستخدم adapter تجريبياً فقط.

## 2. نموذج الموصل

يسجل المضيف موصلاً ذا معرّف ثابت وإصدار ثابت ومجموعة عمليات محددة. لكل عملية دالة تنفيذ وصلاحيات مطلوبة غير فارغة:

```js
{
  demo: {
    id: "demo",
    version: "1.0.0",
    operations: {
      lookup: {
        permissions: ["demo:read"],
        invoke: async ({ payload, signal }) => JSON.stringify({ ok: true })
      }
    }
  }
}
```

لا يستقبل adapter عنواناً يختاره البرنامج. إذا احتاج adapter إلى الاتصال بخدمة خارجية، فعليه استخدام وجهة ثابتة أو قائمة وجهات معتمدة داخل تنفيذه الموثوق، مع تحقق إضافي من DNS/redirects وسياسات منع SSRF في طبقة الموصل نفسها.

## 3. عقد الطلب والاستجابة للمضيف

- request(connectorId, operationId, payloadJson) عملية غير متزامنة.
- connectorId وoperationId معرفان قصيران من سجل المضيف؛ لا يقبلان مسارات أو عناوين.
- payloadJson نص JSON صالح، بحد افتراضي 64 KiB.
- يجب أن تعلن العملية صلاحياتها صراحةً؛ تُرفض العملية ما لم تغطِّ المنحة كل الصلاحيات المطلوبة.
- يتلقى adapter حمولة JSON محللة، ومعرف الموصل وإصداره واسم العملية وAbortSignal فقط.
- يجب أن يعيد adapter نص JSON صالحاً، بحد افتراضي 256 KiB.
- المهلة الافتراضية 10 ثوانٍ، وحد الطلبات المتزامنة 8.
- لا تُمرر رسائل الخطأ الأصلية للموصل إلى البرنامج منعاً لتسريب الأسرار؛ تستخدم رموز أخطاء ثابتة.
- لا تعني المهلة أن adapter غير المتعاون قد توقف فعلياً؛ يجب أن يحترم AbortSignal، وتظل طبقة المضيف مسؤولة عن إغلاق الموارد.

## 4. رموز الأخطاء

| الرمز | المعنى |
|---|---|
| QX_INTEGRATION_INVALID_TARGET | معرف الموصل أو العملية غير صالح |
| QX_INTEGRATION_NOT_REGISTERED | الموصل أو العملية غير مسجل |
| QX_INTEGRATION_PERMISSION_DENIED | لا توجد منحة صريحة كاملة |
| QX_INTEGRATION_INVALID_REQUEST | حمولة الطلب ليست JSON صالحاً أو تجاوزت الحد |
| QX_INTEGRATION_INVALID_RESPONSE | استجابة الموصل ليست JSON صالحاً أو تجاوزت الحد |
| QX_INTEGRATION_TIMEOUT | تجاوزت العملية المهلة |
| QX_INTEGRATION_BUSY | بلغ المضيف حد التزامن |
| QX_INTEGRATION_ADAPTER_FAILED | فشل adapter دون كشف تفاصيله الداخلية |

## 5. حدود هذه الدفعة

- لا ينفذ هذا العقد اتصالات عامة ولا يضيف fetch إلى VM أو Web Runtime.
- لا تُنشأ مفاتيح أو أسرار أو تخزن داخل المستودع.
- لا يوجد موصل إنتاجي حتى اعتماد خدمة محددة ونطاقها ووجهاتها وصلاحياتها.
- لا يستطيع Web Backend الثابت استخدام broker المضيف تلقائياً؛ يلزم جسر تشغيل موثوق منفصل مع CSP وسياسة نشر وموافقة صريحة.
- امتداد QIR 1.3 وربط `INTEGRATION.REQUEST` بمسار VM غير متزامن موجودان في `main`؛ لا تصف هذه الخطوة بأنها قيد التنفيذ.
- `runQIRAsync` هو مسار التنفيذ غير المتزامن، بينما يرفض التنفيذ المتزامن البرامج التي تتضمن `INTEGRATION.REQUEST` بخطأ `QX_VM_ASYNC_REQUIRED`.
- Web Backend الثابت يرفض هذا الأمر بخطأ `QX_WEB_INTEGRATION_UNSUPPORTED`؛ ولا يعني دعم VM غير المتزامن أن المتصفح الثابت يملك broker أو تكاملاً تلقائياً.

## 6. الاختبارات

تغطي اختبارات broker وQIR وVM: السماح/المنع، قصر العمليات المسجلة، صحة JSON، حدود الحجم، إخفاء أخطاء adapter، الإلغاء عند المهلة، حدود التزامن، التحليل الدلالي، QIR 1.3، التنفيذ غير المتزامن، الرفض في VM المتزامن، ورفض البناء للمتصفح الثابت. شغّلها عبر `npm test` داخل `engine/qx-core`. لا تثبت هذه الاختبارات وجود موصل إنتاجي أو اتصال بخدمة خارجية.


## 7. حالة الربط المنفذ وحدود ما يثبته

- سجل الأوامر يفعّل `INTEGRATION.REQUEST`.
- Semantic Analyzer يتحقق من ثلاثة وسائط نصية `TXT` ويحدد ناتجاً من النوع `TXT`، مع أخطاء `QX3050` و`QX3051` و`QX3052`.
- QIR 1.3 يعرّف `COMMAND_CALL` لهذا الأمر بثلاثة مدخلات `TXT` ونتيجة `TXT`.
- VM يوفّر `runQIRAsync` لتنفيذ الطلب عبر broker موثوق يقدمه المضيف. لا يتيح مسار VM المتزامن تنفيذ هذا الأمر.
- Web Backend الثابت يرفض QIR الذي يحتوي `INTEGRATION.REQUEST`؛ يلزم جسر تشغيل موثوق منفصل قبل دعم هذا السيناريو في الويب.
- اختبارات broker وQIR وVM تغطي حالات السماح والمنع والتحقق من JSON والحدود والمهلة والتزامن ومسار التنفيذ غير المتزامن والرفض المتزامن. هذه الاختبارات لا تثبت وجود موصل إنتاجي أو خدمة خارجية متصلة.
- لا توجد موصلات إنتاجية مضمّنة أو أسرار أو وجهات خدمة محددة في المستودع.

هذا التحديث يصحح حالة التنفيذ الموثقة ولا يغيّر عقد الأمان أو يضيف أي صلاحيات أو موصلات.
