# قرارات وملاحظات المشروع

> سجل مرجعي موحد لقرارات مشروع ALI-QX وملاحظاته وتقدمه. يميّز هذا السجل بين ما اعتُمد، وما نُفّذ، وما لا يزال قيد العمل أو غير محسوم.

## 1. القرارات المعتمدة

- مشروع ALI-QX يطوّر لغة برمجة مستقلة باسم QX، موجهة أساساً لبناء مواقع الويب ومشاريعها.
- مجموعات المكتبة الأساسية المعتمدة أربع: UI وDATA وPROCESS وINTEGRATION. لا تُضاف مجموعة رئيسية خامسة إلا بقرار صريح.
- مواصفة قواعد لغة QX V1 معتمدة، مع الفصل بين لغة QX ومرجع الرموز الرياضية الموجود في مجلد Mathematics.
- يعتمد تصميم المحرك تمثيلاً داخلياً موحداً باسم QIR، مع فصل مسار تنفيذ اللغة عن مسار إنتاج مواقع الويب، وفصل كليهما عن بناء أداة QX نفسها.
- Android هو منصة التطوير والاستخدام الأساسية في المرحلة الأولى، ويأتي تجهيز Windows لاحقاً بعد استقرار الأساس.
- لا يبدأ بناء مشروع ويب من وصف المستخدم قبل عرض مخطط المشروع والحصول على موافقته.
- لا تُنفذ التغييرات الجوهرية أو التي توسّع النطاق الموافق عليه قبل موافقة المستخدم.
- تُميّز الوثائق بين القرار المعتمد والمقترح والتنفيذ الذي تم التحقق منه؛ ولا تُعد الميزة منفذة لمجرد توثيق تصميمها.
- لا تُحذف أو تُستبدل أو تُنقل ملفات أو مكونات قائمة دون إذن صريح.

## 2. حالة التنفيذ المسجلة

- مواصفة قواعد لغة QX V1: معتمدة وموثقة في `QX/README.md`.
- نواة المحرك: نُفذت الشريحة الأولى، وتشمل Lexer وParser، وفق الحالة المعلنة في README الرئيسي.
- التحليل الدلالي وQIR وVM وWeb Backend: ما زالت ضمن مراحل التنفيذ، ولا تُسجل هنا على أنها مكتملة.
- مكتبة المكونات التفصيلية، وتواقيع الأوامر والموصلات، وQX Bridge: توجد تفاصيل ومسائل تحتاج إلى استكمال التصميم والتنفيذ والاختبار.
- مرجع Mathematics: مستقل عن لغة QX، والرموز الثمانية المدرجة فيه معتمدة ضمن المرجع الرياضي فقط.
- البرومبت الرئيسي للمشروع: تم تحديث الملف الموجود نفسه إلى الإصدار 2.0 بتاريخ 2026-11-16، دون إنشاء ملف برومبت بديل. يتضمن التحديث قواعد تشغيل المشروع والصلاحيات والموافقات والتوثيق وإدارة المراحل والفروع والأمان والاختبارات ومعالجة الفشل واستمرارية العمل.
  - Commit التحديث: `068d79fbc598bb9b63f5907994dc52521fe84ff9`.
  - الملف: [ALI & ALEX — MASTER PROJECT ENGINEERING PROMPT](../ALI%20%26%20ALEX%20%E2%80%94%20MASTER%20PROJECT%20ENGINEERING%20PROMPT).

## 3. المسائل المفتوحة والنواقص

بحسب وثائق المشروع الحالية، ما زالت الأعمال التالية بحاجة إلى استكمال أو حسم تنفيذي:

- التحليل الدلالي وتشخيص الأخطاء واختبارات المطابقة.
- التصميم التنفيذي التفصيلي لـ QIR وتنفيذ مسار التحويل.
- تنفيذ VM واختبارات التشغيل والمعاينة.
- تنفيذ Web Backend والتحقق من إنتاج مواقع ويب فعلية واختبارها.
- استكمال تواقيع أوامر ومكونات UI وDATA وPROCESS وINTEGRATION واختبارها.
- تفاصيل موصلات INTEGRATION وصلاحياتها.
- تفاصيل QX Bridge واللغات والبروتوكولات المدعومة.
- نظام المشاريع والبناء الجزئي والنسخ الاحتياطي وسجل العمليات.
- تطوير QX Studio على Android، ثم تجهيز Windows واختباره في المرحلة اللاحقة.

هذه قائمة مستخلصة من الوثائق المرجعية الحالية، وليست حكماً بأن كل بند لم يبدأ العمل عليه؛ يجب تحديث حالة كل بند عند توفر تنفيذ أو اختبار موثق.

## 4. قواعد تحديث هذا السجل

1. يُضاف القرار إلى قسم القرارات المعتمدة بعد موافقة المستخدم فقط.
2. تُسجل الاقتراحات غير المعتمدة بوضوح على أنها مقترحات، ولا تُمزج بالقرارات.
3. عند تسجيل إنجاز، يُذكر ما نُفذ فعلياً وما اختُبر ونتيجة الاختبار، مع رابط الملف أو الالتزام البرمجي عند توفره.
4. تُسجل المشكلات والنواقص المفتوحة دون الادعاء بحلها.
5. لا يُحذف قرار سابق أو يُستبدل بصمت؛ يوثّق أي تغيير مع سببه وتاريخ اعتماده.
6. يُحدّث هذا السجل عند اعتماد قرار أو إنجاز مرحلة أو اكتشاف مشكلة مؤثرة، مع إبقاء التفاصيل الفنية في وثائقها المتخصصة.
